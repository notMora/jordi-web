# Website Content Structure

## Brief intake (input contract)
Accept natural language, and normalise it to these fields in `.web-work/brief.md`. Mark each value as **given**, **inferred** (`ASSUMPTION:` plus the reason) or **missing**:
NICHE / SECTOR · TARGET AUDIENCE · PRIMARY GOAL · SECONDARY GOAL(S) · PAGES NEEDED · PRIMARY CTA · SECONDARY CTA(S) · REFERENCE URL(S) · BRAND NAME · BRAND COLORS / STYLE · ASSETS · COPY / KEY MESSAGES · FUNCTIONAL REQUIREMENTS · TECH STACK (optional) · SPECIAL CONSTRAINTS.

Infer only what the brief, workspace or references safely support. Ask the user only about missing items that block the work, and only if they can't be discovered.

## Section selection by niche
Derive sections from the goal and audience rather than a fixed template. Typical modules to choose from:
hero · value proposition/benefits · offer (menu, collection, products, services, packages) · how it works/process · featured item/story · about/brand story · social proof (reviews, press, clients) · gallery/portfolio · pricing · location/hours/contact · booking/reservation/purchase flow · FAQ · final CTA · footer (NAP, legal, social).
Examples of niche fit (adapt, don't hard-code): hospitality leans on the offer + atmosphere + booking + location; luxury on craft/story + collection + appointment; local services on trust + service area + fast contact; e-commerce on product + proof + purchase.

## Copy rules
- Put the message hierarchy first: in 3 seconds the hero must say *what*, *for whom*, *why this one* and *what to do next*.
- CTAs are verb-first and specific ("Book a table", "View the collection"), never "Click here" or "Submit".
- Write original copy. Never reuse a reference site's text.
- **Never invent business facts**: prices, awards, years in business, ratings, review quotes, client logos, certifications, addresses, hours, stats. Use `[PLACEHOLDER: what is needed]` and list every placeholder in the handoff.
- Keep copy in data/content files so it's easy to replace. Use the brief's language, or ask if it's ambiguous.
- Aim for SEO-friendly clarity: a descriptive heading hierarchy, a natural use of the niche and location terms the brief supports, and no keyword stuffing.
