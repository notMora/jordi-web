# Quality and safety

- Never copy a reference site's proprietary text, logos, brand assets, source code or unique artwork. Recreate the design language with original code, original copy, and licensed or user-provided assets.
- Never fabricate research results, trends, popularity, traffic, awards, dates, business claims, testimonials, prices, performance metrics or external facts. Mark unknowns as `[PLACEHOLDER: …]` and inferences as `ASSUMPTION:`.
- Separate observed facts from interpretation in every analysis.
- If a tool fails, use this fallback order: narrower retry → another browser/search method → user-provided screenshots/assets → proceed with clearly marked assumptions → document what could not be verified.
- A page is not done because it compiles. It is done when it has been checked in a real browser (desktop and mobile) against the quality gates in the `visual-browser-qa` skill.
- Respect the existing stack and conventions. Do not refactor unrelated code or add dependencies without a stated reason.
- Fix priority: broken functionality > layout breakage > readability/accessibility > visual polish.
